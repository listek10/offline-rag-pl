# PODZIAŁ NA DWA PLIKI — kryterium jest "kto tego potrzebuje", nie "który to etap":
#   requirements.txt      -> uruchomienie systemu (parsowanie, embeddingi, Qdrant, serwer)
#   requirements-dev.txt  -> weryfikacja kontraktów (61 MB venva, BEZ GPU i bez usług)
# Powód: ten plik ciągnie torcha (~2,5 GB) tranzytywnie, przez sentence-transformers.
# Gdyby testy od niego zależały, "sprawdź, czy repo działa" kosztowałoby 2,5 GB pobierania.
#
# ┌─ TORCHA TU CELOWO NIE MA ─────────────────────────────────────────────────────────┐
# │ `sentence-transformers` WYMAGA torcha, więc pip i tak go pobierze — ale z PyPI,    │
# │ a build z PyPI nie ma kerneli pod tę kartę (RTX 5070 Ti = Blackwell / sm_120).     │
# │ Objaw jest podstępny: instalacja przechodzi, a "no kernel image is available"      │
# │ wybucha dopiero przy pierwszym .encode(), daleko od przyczyny.                     │
# │ Dlatego torcha instalujemy PRZED tym plikiem, z indeksu CUDA (patrz README):       │
# │     pip install torch --index-url https://download.pytorch.org/whl/cu128          │
# │     pip install -r requirements.txt        # <- widzi torcha jako spełnionego      │
# │ Kolejność ma znaczenie. Odwrotna daje zły build i "działa, ale nie na GPU".        │
# │ Świadomie NIE wpisujemy tu `--extra-index-url`: ta flaga nie jest przypisana do    │
# │ paczki, obowiązuje CAŁY resolving — pip mógłby wziąć z indeksu PyTorcha dowolną    │
# │ inną zależność. Plus przybiłaby plik do jednej architektury GPU.                   │
# └───────────────────────────────────────────────────────────────────────────────────┘
